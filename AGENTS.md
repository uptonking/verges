# AGENTS.md

## Purpose
Reproducible single-node VPS Docker services stack. Caddy is the TLS entrypoint and foundation; consumer services (e.g. the `verges` Hysteria2 proxy) are toggleable via compose profiles. Desired state is committed to git (`config.env`); secrets stay on the VPS (`.env`).

## Repository Role
- Category: `*-self-hosted` (public GitHub repository).
- Main entrypoint: `docker-compose.yml`, operated exclusively via `scripts/*.sh`.
- Daily flow: push to GitHub → `scripts/deploy.sh` on the VPS.

## Stack Summary
- Services: `caddy` (always on), `verges` (profile `verges`, Hysteria2), `gost` (profile `forward`, TCP relay).
- Exposed ports: `80/tcp`, `443/tcp` (caddy), `443/udp` + `20000-30000/udp` (verges), `8443/tcp` (gost, configurable).
- Network: `shared_network` (bridge, **owned by this stack** — future stacks attach with `external: true`).
- Companion: `indigenous-node/` self-contained script suite for the 3x-ui/xray egress VPS.

## Data and Config
- `config.env` — committed desired state (profiles, domain, `VERGES_PORT`, `VERGES_HOP_RANGE`, image pins). VPS IP is intentionally not stored; DNS A record is the source of truth.
- `.env` — gitignored secrets (`SSL_EMAIL`, `VERGES_PASSWORD`); generated by `scripts/bootstrap.sh`.
- `caddy/` — Caddyfile + `sites/*.caddy` per-service site files (mounted read-only).
- `services/verges/config.yaml.template` — envsubst source for the Hysteria config.
- `data/caddy/` — caddy runtime/certificate storage (gitignored).

## Operations
- Bootstrap fresh VPS: `scripts/bootstrap.sh`.
- Apply git state / enable-disable services: `scripts/deploy.sh`.
- Others: `restart.sh`, `stop.sh`, `status.sh`, `logs.sh`, `update.sh`, `caddy-reload.sh`.

## AI Working Notes
- **UDP 443 belongs to verges.** Never re-add `443/udp` to caddy; keep `servers { protocols h1 h2 }` in the Caddyfile (h3 disabled).
- **The ACME issuer pin in `caddy/sites/verges.caddy` is load-bearing**: it makes the certificate storage path deterministic (`data/caddy/certificates/acme-v02.api.letsencrypt.org-directory/...`), which `services/verges/config.yaml.template` references exactly. Removing it breaks verges.
- **Both env files are required** on every compose invocation: `docker compose --env-file config.env --env-file .env ...` (wrapped as `compose()` in `scripts/lib/common.sh`). `config.env` is NOT auto-loaded by compose.
- Hysteria has no env-var config — always regenerate `services/verges/config.yaml` from the template (`gen_configs`) after changing domain/password.
- Hysteria hot-reloads certificates (mtime checked per handshake); no restart needed on cert renewal.
- Reboot recovery relies on `restart: always` + `systemd enable docker`; profiles do not block daemon-level restarts.
- Extend `gen_configs()` in `scripts/lib/common.sh` when adding a new service with templated config.
- Port hopping requires `network_mode: host` + `cap_add: [NET_ADMIN]` on the verges container (the official image includes iptables/nftables). This lets hysteria bind the range directly on the host and install DNAT rules, avoiding docker-proxy. The hopping range is controlled by `VERGES_HOP_RANGE` in `config.env` and must match the client config.
- The verges container uses host networking, so its masquerade backend points to `https://127.0.0.1` (caddy on the same host), not `https://caddy`.
- **gost (`forward` profile)** is a raw TCP byte-pipe: `tcp://:FORWARD_PORT/FORWARD_TARGET`. It does not terminate TLS. The VLESS+Reality handshake runs end-to-end with xray on the indigenous node.
- **No VPS IPs are committed to git.** `FORWARD_TARGET` uses the `edge-direct.<domain>` DNS name; the indigenous-node `NODE_HOST` is also a DNS name.
- **Indigenous node** uses 3x-ui installed directly (no docker) because the VPS is too small (1 CPU / 512 MB / 3 GB). Secrets are generated by `indigenous-node/bootstrap.sh` and kept in `indigenous-node/.env`.
- **Indigenous node runs two VLESS+Reality inbounds sharing one UUID/keypair**: `direct` on 443 (standalone, `edge-direct.<domain>`) and `relay` on 8443 (gost target behind primary). `*_INBOUND_ENABLE` flags in `indigenous-node/config.env` are the source of truth on `deploy.sh`; webapp toggles are temporary.
- **Hysteria2 (QUIC) is the low-latency edge transport**: standalone hysteria2 server (pinned binary, systemd unit, self-signed ECDSA cert, password in `.env`) on UDP/443 for direct mode; primary's gost has a matching `udp://` listener (`FORWARD_TARGET_UDP`) so the relay mode works over UDP too. VLESS+Reality stays as TCP fallback (~3 RTT handshake vs ~1 RTT). Hy2 uses ~6 MB RAM — fine on the 512 MB box.
- **REALITY dest/SNI is www.apple.com on purpose.** www.microsoft.com breaks mihomo: xray borrows the target's TLS flight shape and Microsoft's record segmentation stalls non-xray clients after the server flight (REALITY auth succeeds, TLS handshake never completes). Apple works; verified via a standalone `xray run` with `"show": true`.
